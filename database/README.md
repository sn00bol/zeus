# Shared PostgreSQL database

The root `database/` directory owns the PostgreSQL schema and connection
shared by platform adapters. `compose.yaml` runs PostgreSQL and persists its
data under `database/postgres/`; run the project through `python app.py` to
start PostgreSQL before the inference bridge and Discord client.

Shared services live in `core/`: `database.js` is the Node.js database router
used by platform adapters and future WebUI code, while `database.py` provides
an async PostgreSQL connection for Python services. Both use this directory's
schema. Conversation sessions are keyed by platform and conversation ID;
messages continue to use the platform-neutral `chat_messages` history.
The separate `conversation_memories` table stores user-scoped relevant
question/answer pairs with a 30-day sliding expiry; expired rows are removed by
the Python bridge lifecycle service.

Curated or explicitly extracted user facts are stored separately in
`extracted_memories`; they are not inferred from or mixed with raw conversation
turns. Both stores are scoped by platform and user, share the configured
retention period, and are removed by the same forget operation. NumPy is an
optional `search` extra and is used only for vector similarity; embedding
generation requires a separately configured provider.

Conversation messages are stored as JSONB with a platform-neutral JSON payload
so another platform can reuse the same history format. Export and import with
`node database/history.js export [file.json] [platform]` or
`node database/history.js import [file.json] [platform]`. Imports are
transactional; repeated imports do not duplicate messages with the same
platform and message ID.

`model_preferences` stores one provider/model selection per Discord server,
or per user in DMs; a null selection means discover a local model for each
request. `model_configuration` stores ZEUS's default provider, model, and
optional Ollama API key. `chat_threads` marks public Discord threads started from a message
mention for ZEUS chat.

Keep `.env` private. PostgreSQL binds to localhost by default, and its
password is generated by `python setup.py`. Model configuration is managed
with `python setup.py` and is stored in PostgreSQL rather than `.env`.
